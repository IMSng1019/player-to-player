# 世界元数据同步（控制协议 v9）

`level.dat` 与 `level.dat_old` 不再作为环境文件传输。中心服持有世界字段的权威状态，计算组通过有类型 NBT 快照、带版本补丁和应用确认更新运行对象。环境扫描、历史快照恢复、下载、中转缓存及环境上传均使用实际存档路径排除这两个文件；`session.lock` 同样不属于环境资源。

## 升级与文件布局

- 中心服、中转端和客户端必须同时升级至控制协议 **9**，旧协议连接会被拒绝。
- 首次运行从中心服的原版存档导入字段；运行后采集内存对象，避免读取尚未保存的旧文件。
- 元数据位于 `player-to-player/world-metadata/<世界生成身份>/`。世界身份沿用现有 `WorldIdentity` 规则；与既有机制一样，保留同一生成身份却人工替换世界的情况不能仅靠生成哈希辨别。
- 每次计算进程启动，即使已有缓存，也重新请求权威快照。覆盖全局字段时保留独立 `Data.Player` 和本组 `Time`，随后继续执行既有玩家数据安装流程。
- 计算实例的难度、默认游戏模式、极限模式启动参数以本次快照为准。
- 正在运行的实例只通过服务器线程/RPC 应用字段，合并期间不覆盖其存档文件。

## 版本、持久化与确认

快照包含 `worldId/version/term/data`。补丁包含世界身份、基础版本、新版本、任期、操作 ID、替换字段及独立删除集合。数据保存原始 NBT 类型。

离散变更在 WAL 强制落盘后返回确认；同一操作 ID 重试读取首次提交结果，不能重新执行相对命令。操作 ID 被不同载荷复用会被拒绝。自然计时每 20 个中心逻辑 tick 保存检查点，不为每秒计时永久累积操作回执。正常停服提交最后状态并关闭存储。

新任期以及自然检查点之后的首次离散提交还会把完整恢复基准写入固定 WAL 文件并强制落盘。这样即使掉电后目录项仍指向旧检查点，后续已确认操作也能从日志恢复，不依赖原子改名本身等同于断电持久化。

任期在中心恢复以及组写入者集合变化时递增。过期任期、错误世界身份和字段权限不符均拒绝。客户端正常接收连续补丁；缺口优先读取最近256条连续日志窗口，窗口不足、合包过大或任期变化时退回完整快照。补齐与 ACK 之间发生任期切换时，原同步 RPC 在期限内重新获取快照，不把瞬时竞争当作启动成功或静默放行。

`METADATA_ACK` 只证明字段已应用。合并仍必须通过原有区块尾部、接收端和隧道屏障；额外检查计划任期及最低元数据版本。分离在准备、排空及最终提交处检查字段和不可迁移状态，失败走原组恢复路径。

源端冻结后还会提交最后的模拟所有者字段；源和目标再通过双向版本屏障，确认目标已应用这一尾部后才允许提交迁移。正常退出也先提交字段尾部再关闭计算进程。当前分离采用保守冻结覆盖旧区域排空过程，包括留组玩家的模拟，不能承诺所有分离都在300ms以内。

## 字段与运行时规则

| 类别 | 行为 |
| --- | --- |
| 生成设置、数据包、版本、极限模式等启动字段 | 打开世界前安装；运行中发生需重载的变化时安全退出计算世界，并提示重新连接 |
| 游戏规则、难度、默认模式、出生点 | 调用原版运行时入口，保留变更回调、必要副作用和通知 |
| 世界边界 | 同步采样时的大小、目标和剩余时长；补齐扣除已经经过的时间，相同镜像不重新开始渐变 |
| 昼夜和天气 | 中心唯一推进；每秒发布基准，天气切换及命令立即提交；计算端保留原版天气视觉渐变及发包 |
| `Time` | 中心用于计划事件逻辑时钟；每个计算组保留自己的模拟时钟，不被昼夜修正回拨 |
| 自定义 Boss 血条 | 同步定义和 UUID 名单，显式删除旧条目，并绑定本地在线玩家；复杂玩家选择器在原执行上下文解析 |
| 计划事件 | 中心唯一计时并派发一次，计算端禁止执行同步队列；函数使用原版服务器命令源，不继承发起玩家实体 |
| 末影龙 | 由末地中心区块的唯一持有组推进，其他组只保留镜像；复活中间态拒绝接管 |
| 流浪商人 | 中心唯一推进生成机会，向一个目标玩家所在组派发原版生成尝试；同步存档字段和生成器缓存 |
| 玩家、记录及未知字段 | 玩家走独立通道；记录字段不因自动保存触发业务补丁；未知字段保留，但不隐式授予客户端覆盖权 |

跨组睡眠按维度、玩家 UUID、当前成员关系、旁观状态和深睡状态汇总，遵守 `playersSleepingPercentage` 及相关游戏规则。缺少新鲜组报告时延迟跳夜；一次判断只执行一次全局跳夜，并只唤醒相应维度的玩家。

分布式元数据服务活动期间，中心世界保持轻量全局状态推进，不恢复区块/实体模拟。调试配置 `suspendWorldTick=false` 也不能让中心再次成为同一世界的第二个模拟写者。

## 命令与计划函数

`time/weather/gamerule/difficulty/defaultgamemode/setworldspawn/worldborder/bossbar/schedule` 的变更集中提交。`/execute` 包装的全局叶命令也不会按组重复广播；在实际叶执行点保留原执行上下文，局部/相对坐标先求出绝对值。命令返回的成功标志与整数返回值分别传输，成功返回 0 不会被误判为失败。

计划函数的稳定调用 ID、目标组/成员路由和派发状态单独持久化。组变化后重新解析目标；控制台创建的计划也会选择一个明确计算组，不依赖出生点恰好有人加载。派发前耐久移出待执行队列，执行端先写 `started` 标记，再运行函数。明确回复 `notStarted` 才可以重新排队；网络超时或执行结果不明保留 `unknown` 供核查，绝不自动重放非幂等函数。成功状态保留有限诊断窗口。

函数和生成尝试使用普通服务器任务队列，不能持专用迁移控制队列锁等待网络响应。迁移冻结、退出排空和旧写者退休期间拒绝新的非幂等调用。

## 模组适配

实现并注册 `MetadataAdapter`，声明独占的顶层字段、所属类别、内存采集方法、启动应用、运行应用及资源写入授权。`SIMULATION_GROUP` 的 `canWrite` 默认拒绝；中心验证当前主客户端以及适配器声明的授权。适配器可通过 `MetadataEvents.propose` 提交自然变更，也会参与低频采集。

应用权威镜像时启用内部回放标记，避免回调再次上报。适配器必须正确处理字段删除，并在适当的 Fabric 初始化阶段注册；仅保存未知 NBT 不代表未知模组的运行对象能够热更新。

本功能不承诺全部实体、模组内存状态的无感迁移。末影龙复活动画等现有迁移链路未覆盖的中间态保持拒绝接管。启动字段变化目前采用耐久退出后重新连接，不进行静默自动重连。

## 验证命令与范围

```powershell
.\gradlew.bat test
.\gradlew.bat build
.\gradlew.bat test -Pp2pMetadataSmoke -Pp2pSmokeJavaVersion=17 --tests '*MetadataProcessSmokeTest'
.\gradlew.bat test -Pp2pWorkerSmoke -Pp2pSmokeJavaVersion=17 --tests '*WorkerProcessSmokeTest'
```

真实进程测试启动一个中心 Fabric 服务端和两个独立 Fabric 计算 JVM，产物仅写入 `build/metadata-smoke/`。它验证重复操作去重、单组丢补丁后的补齐、Boss 删除后重同步、边界渐变、计划函数单次执行及无玩家实体执行源、实际控制断开后的模拟暂停、重连和旧任期拒绝。

2026-10-25 最终验收命令：

```powershell
.\gradlew.bat test build -Pp2pSmokeJavaVersion=17 -Pp2pMetadataSmoke -Pp2pWorkerSmoke
```

结果为 **650项测试、0失败、0错误、0跳过**，构建成功。三端日志均确认使用 Java17。最新真实进程记录位于 `build/metadata-smoke/1792907049971/result.json`：两个计算组状态可见的采样时间251ms，缺口通过1次增量补齐完成且没有快照回退，旧历史请求正确回退快照；计划函数515ms完成且全局只增加77；重连任期4→6，断线期间本组模拟时钟保持391。

观察器约每250ms采样一次，上述传播时间不是精确网络单程延迟，更不是全网逐tick严格同步。耗时断言曾捕获并验证修复了约15秒的控制队列锁等待。原版 `time query gametime` 在玩家所在计算组查询本组时钟，不用中心计划事件时钟替代。

自动测试另外覆盖字段保留/删除、操作去重、版本冲突、任期变更、损坏与断尾恢复、睡眠人数判定、运行对象更新、环境排除和迁移拒绝屏障。真实玩家进入床铺、末影龙复活动画、自然商人实体生成以及复杂模组组合仍需游戏场景验收；不能把无玩家的三进程控制面测试等同于这些场景已经验证。
