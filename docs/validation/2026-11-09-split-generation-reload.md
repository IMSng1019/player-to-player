# 2026-11-09 世代外圈分离阻塞验收

## 现场根因

`test_log/26.11.9/server/latest (23).log` 记录了 21:51:54 传送到原点后约 76 秒没有准备分离；21:53:42 才开始一次正常分离，21:53:47 提交，新组随后启动。成功分离发生在原主退出前，因此不能将整轮测试概括成“完全没有分离”，也不能把最后一次成功当作此前长时间等待正常。

进一步只读查到本机实际计算进程日志。21:52:08、21:52:40、21:53:12 连续延期，均为 `完整加载岛尚不可交接`：视距 10，玩家区块位置约 `(0,-1)` 与 `(32,34)`，3855 个占用，无特殊票据。规划把需求扩大为半径 `10 + 12 + 2 = 24`。追加日志也确认 11/8 卡在同一加载岛条件。

现场模组与上轮构建 SHA-256 完全一致，排除了旧包。上轮修复的元数据检查点竞争是真实问题，但不是此现场的主因。

## 修复行为

普通分离路径继续使用原有预约、写回、卸载和提交。对渲染范围已经远离、普通加载及光照邻域也已分开，而历史世代外圈仍把两侧连成一岛的情况，新增完整原组重新加载的回退路径：

1. 等待所有实际产生玩家加载需求的成员，其 `viewDistance + 2` 范围已为 FULL，保存依赖成功完成；不要求禁止生成区块的旁观者加载不存在的范围。
2. 预约完整旧组范围，通知全组暂离游戏连接，保留计算进程与控制连接。由原版玩家退出撤销 PLAYER 票据、关闭菜单及结束玩家实体生命周期。
3. 等待全部参与者最终玩家数据确认、区块耐久释放及旧 holder 卸载，之后才提交分组。
4. 原 worker 收到终态并解除加载围栏后报告 `source_ready`；中心再允许留组成员重连，原主复用现存 worker。取消也走确认后的恢复，退出接替／旧连接不得恢复旧源。

准备后若参与者跨区块移动，原先 FULL 验证范围可能失效，完成写回后取消并恢复原组。独立传送门、强制加载等票据继续受保护，不手删 holder，不提前释放所有权。

受影响的场景会有一次全组加载等待，本次不承诺 300ms 无感热备。

## Windows 安装边界

全量测试两次遇到新计算进程安装暂存目录原子重命名 `AccessDeniedException`，发生在进程启动前。新增真实 Windows 禁止共享删除文件句柄测试，确认单次移动失败，句柄释放后可重试成功。

安装、备份及回滚共用有界移动入口：仅 Windows 的访问拒绝允许在两秒窗口内重试；等待前后核对源仍存在、目标明确不存在。目标已存在、其他 IO 错误及中断不继续尝试，也不修改权限。七项专项测试覆盖真实暂时占用、永久拒绝、源／目标变化、原子移动回退和中断；单次移动基线有三项失败，新实现通过。
