# 2026-11-09 分离与元数据检查点时序修复

## 日志与结论范围

依据 `player_to_player-prompt.txt` 和 `test_log/26.11.8`。中心日志能确认两名玩家同组运行、发生远距离传送，并且持续上报玩家状态；23:29:59 的“组已分离”属于主客户端退出接管。两个客户端日志都在环境自动重启前结束，缺少本轮实际计算进程的分离诊断。因此不能将现场所有“不能分离”的情况都归为同一原因。

本次复现并修复了 level.dat 字段同步新增的一项时序阻塞：中心分离请求原先在网络线程直接执行，元数据检查点却在中心主线程发布。检查点在途时，准备会被 `metadata_transfer_unsafe` 拒绝，提交会被 `metadata_barrier_changed` 拒绝并触发安全回滚。周期重试即使错开到 23 tick，也不能保证请求发生在检查点发布之后。

## 修改

- 所有分离阶段共用中心主线程入口：先等待并发布已经在途的检查点，再校验当前控制会话，随后进入协调器和注册表临界区。检查点等待发生在会话及协调器锁之外。
- 绑定处理器所属的元数据服务实例；关闭、替换实例、过期连接、调度失败和持久化失败均明确拒绝，不因服务销毁而绕过检查。
- 保留世界身份、任期、最低版本、特殊加载票据、区块最终写回和唯一写者限制。
- 分离区域尚不可交接时，日志输出实际离组/留组需求、占用数量和特殊票据范围；仍按稳定原因节流。

此入口在分离请求到达时可能等待一次既有磁盘写入，与现有离散元数据变更使用相同耐久屏障。它不改变普通快照、确认或每秒状态报告的非阻塞读取流程。
