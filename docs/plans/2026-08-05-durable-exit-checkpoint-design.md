# 主客户端两秒耐久退出设计

## 目标与边界

正常网络下，从玩家点击退出开始，到物理服务端确认“最终玩家数据、最终区块尾部、退出事务终态以及 ownership release 已经耐久记录”为止不超过两秒。网络断开、服务端重启或 ACK 丢失时，客户端不得放弃事务，必须保留同一 `shutdownId` 持续重连并查询/重放，直到收到耐久确认。

两秒目标不能依赖退出瞬间临时上传无限量数据。运行期必须持续做耐久检查点，使退出债务只包含最后一次 ACK 之后的尾部变化；日志中的 1654 个区块、约 7.2 MiB 场景仍作为最坏回归样本验证。

## 根因

26.8.5 日志中，客户端在 `13:48:59` 收集完 1654 个区块、7,278,191 字节，直到 `13:49:56` 才收到提交确认，耗时约 57 秒。旧链路把每个区块作为独立请求串行等待 ACK，并在服务端对暂存文件、事务 JSON、正式区块、注册表快照和清理状态执行多次同步刷盘。批量上传只能减少 RTT；如果 `EXIT_COMMIT` 仍同步执行多层 force、MCA flush 和 JSON checkpoint，就无法严格控制在两秒内。

## 核心设计

### 1. 运行期检查点

主客户端按区块键合并最新快照，以稳定的 `(sessionBatchId, sequence, hash)` 批量上行。服务端对每个实时批次只追加一次世界级 WAL 并 `force` 一次，随后返回 `durableEpoch`。MCA 是异步物化视图，读取优先查询 WAL 最新索引。

ACK 丢失时必须逐字节重放原批次。服务端先查询已耐久批次身份，再做当前 ownership 校验；已耐久重放即使区块随后释放，也应返回原 ACK。客户端释放在途批次中的任一区块时取消整个在途批次及其本地 ACK 等待、推进 sequence，并立即用新 sequence 重发剩余区块，不进入网络退避。

普通 `CHUNK_RELEASE` 的最终 WAL 写入与 ownership 回执提交必须共享同一个线性化区间。锁序固定为“区块条带锁 -> 批次 WAL 锁 -> registry claimLock”，从而保证运行期批次只能完整发生在释放之前，或在 ownership 删除后被拒绝，不能插入最终快照与所有权删除之间。

### 2. 退出暂存

`EXIT_PLAYER_DATA`、`EXIT_CHUNK_DATA` 和 `EXIT_CHUNK_BATCH` 只做完整校验并写入事务暂存区，不执行 `force`，其 ACK 只表示“本次连接已接收”，不表示耐久。若服务端在最终提交前崩溃，客户端从 `EXIT_BEGIN` 重新发送即可，因此这里无需为可重建缓存支付同步落盘成本。

### 3. 分段复合提交事务

`EXIT_COMMIT` 从暂存区组装一个逻辑复合 WAL 事务，内容包括：

- 全局单调 `durableEpoch`、`shutdownId`、`clientId`、`groupId`；
- 服务端确认过的玩家与 ownership 清单；
- 最终玩家 NBT；
- 实际写入的区块键、版本、压缩 NBT 与 SHA-256；
- 事务 `COMMITTED` 终态和 ownership release 语义；
- 数据片序号、格式版本、SHA-256 与 CRC32；
- 终结标记中的数据片总数、逻辑总长度和总 SHA-256。

逻辑载荷按有界数据片写入，末尾追加终结标记，全部记录共用一次 `FileChannel.force(true)`。恢复时只有数据片连续完整、总长度和总摘要均与终结标记一致，才发布 committed；没有 marker 的完整前缀只视为未确认孤儿数据。force 成功后，服务端在内存中发布 committed 状态并立即返回 `committed=true`；ownership 仍保持冻结，随后按 WAL 中的释放意图后台清理。这个 ACK 同时证明最终数据、事务终态和所有权释放意图均可在崩溃后恢复，不再等待 JSON、MCA、玩家文件或注册表全量快照，也不再受单条 128 MiB 物理记录上限约束。

### 4. 异步物化与恢复

ACK 后后台幂等执行：玩家文件原子写入、区块 MCA 写入、注册表 JSON/checkpoint、组表清理、事务暂存删除。任一步失败都持续重试，但不撤销已经耐久的 commit。

服务端启动时先扫描 WAL，再开放控制端口：

- 完整中段损坏或未知格式必须拒绝启动，不得截掉后续已 ACK 数据；
- 只有可证明不完整的最后一条记录可以截断；
- epoch 只允许严格递增，写入结果不确定时允许空洞，禁止回滚复用；
- 按日志顺序恢复区块最新索引、pending/committed 退出事务和 ownership release；
- committed 记录可重复物化，后续更高 epoch 的新 owner 数据始终覆盖旧退出数据。

### 5. 断网与身份安全

客户端每次重连先发 `EXIT_STATUS`。已 committed 直接结束；pending 则继续缺失数据和 commit；服务端无状态时重放 `EXIT_BEGIN`。

普通断连释放 ownership 时，服务端必须同时耐久保存由权威注册表生成的恢复凭证。孤儿退出恢复只能使用该凭证的完整清单，不能信任客户端自报坐标。正常重新加入会消费凭证，防止旧退出包在未来复用。

### 6. 世界隔离与日志生命周期

WAL 路径绑定稳定世界身份，至少包含服务端存档根的规范化标识和 `level-name`，不同世界不得共享区块坐标空间。WAL 使用分段文件；完成异步物化并写入 checkpoint 后可删除已覆盖旧分段，限制文件大小、启动扫描时间和幂等索引内存。

## 时间预算

在 RTT 不高于 80 ms、持续上行不低于 50 Mbps、服务端 WAL force p95 不高于 150 ms 的正常网络/磁盘条件下：

- 本地冻结与原版最终保存：目标不超过 700 ms；
- 最终尾部传输：目标不超过 850 ms，正常稳态应接近零；
- 复合 WAL 编码与一次 force：目标不超过 250 ms；
- 协议与线程调度余量：200 ms。

超过传输预算的数据不能通过省略耐久来伪装成功；客户端继续等待并记录 `exit.final_bytes` 与各阶段耗时，以便定位运行期检查点欠债。

## 验收

- 1654 个区块、约 7.2 MiB、1 个玩家的复合提交只发生一次 force，完整 handler 到 durable ACK 小于 2 秒。
- 无新增修改时退出 `final_bytes` 接近零；修改 100 个区块时只提交这 100 个区块。
- ACK 丢失、提交前/后服务端崩溃、断网重连、重复 commit 均不丢数据且不重复释放新 ownership。
- 实时批次 ACK 丢失后释放其中一个区块，不得永久阻塞剩余上传。
- 最终释放 WAL 写入后暂停 ownership 提交时，并发运行期批次必须保持阻塞；提交后该批次因无 ownership 被拒绝。
- 三条 WAL 记录损坏第二条时拒绝启动且文件不被截短；撕裂尾记录只截断尾部。
- durable 批次前缀后的完整孤儿退出 parts 只回收尾部，前缀保留且同一 `shutdownId` 可重新提交。
- 不同世界使用不同 WAL，旧世界数据不得出现在新世界。
