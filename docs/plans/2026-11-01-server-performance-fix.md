# 中心服环境快照与持久化性能修复实施计划

**目标：** 消除玩家存档驱动的全环境复制，降低同步持久化开销，并保留原有数据恢复与确认语义。

**架构：** 依据已确认的诊断方案，统一实际世界路径的玩家数据排除规则；快照仓库复用经验证且未失效的 Blob，监视事件定向失效、周期校验兜底，遍历直接跳过排除子树。元数据保持服务器线程采集与有序提交，将周期持久化重活移出主线程；玩家 NBT 验证后复用原压缩字节。协议版本和消息类型保持不变。

**技术栈：** Java 17、Fabric 1.20.4、Java NIO WatchService、JUnit 5、Gradle wrapper。

用户已批准上一轮方案并要求完成后自行 commit；本轮直接实施、测试、审查并提交，不重复询问设计或提交许可。工作区原有 `docs/ENVIRONMENT_RUNTIME.md` 和需求文件改动保持原样，不纳入本次提交。

## 1. 玩家文件分类

- 修改 `EnvironmentPathPolicy`、`P2PServerService` 及需要的中转/下载调用点。
- 先补默认和自定义世界路径、玩家原子替换不推动环境版本的回归测试并确认旧实现失败。
- 排除完整 playerdata 目录，保留既有玩家专用通道及 datapacks/serverconfig；不直接排除尚无独立同步覆盖的所有世界数据。

## 2. 环境快照增量构建

- 修改 `EnvironmentSnapshotStore`、`EnvironmentSnapshotManager`；增加相应存储/监听回归测试。
- 先证明单个配置变化不应重复制未变模组、重复刷新不应产生临时副本、相同大小和时间戳的已通知修改仍能被识别。
- 缓存稳定读取后的文件版本与 Blob 条目；监视事件按路径失效，未知变更/溢出回退校验。周期校验覆盖漏事件，删除重建和 Blob 缺失可恢复。
- 遍历进入目录前剪枝；构建期间事件合并并延迟下一轮；相同 ID 不重复发布。
- 将失效旧清单移入隔离目录并汇总记录，避免启动反复告警。

## 3. 持久化开销

- 修改 `PlayerDataFileStore`，用回归测试证明有效压缩字节原样保存、非法 NBT 不覆盖旧档、退出顺序保持。
- 元数据优化由独立任务核查并实现：不可变采集、后台有序持久化、完成后才发布版本；必须覆盖慢盘、失败、任期/离散请求交错以及关闭排空，不允许提前确认未落盘状态。

## 4. 集成验证与提交

- 分组件先运行失败测试，再运行修复后的针对性测试。
- 运行 `.\gradlew.bat test build`，必要时执行现有 Java 17 真实进程冒烟。
- 在隔离临时目录执行环境更新/玩家写回模拟，记录实际构建/复制行为；不把此结果冒充真实多人游戏性能采样。
- 独立审查正确性、并发、恢复和兼容行为，解决实质问题。
- 更新本计划的验证记录，检查差异，只提交本轮代码、测试和诊断/实施文档。

## 实施结果

已完成以下修复：

- 默认与实际存档路径的 `playerdata` 由中心/中转/下载端共用同一排除规则；旧清单在升级后拒绝继续分发玩家文件。玩家专用数据通道保留。
- 环境构建按具体文件/目录事件失效缓存，复用未变化 Blob；重复刷新不写临时副本，定期内容校验可识别同大小同时间戳的漏报修改。扫描和监听注册直接跳过排除子树。
- 构建窗口从首事件计时，连续通知不会无限拖延；构建期间到期的周期校验保留到下一轮执行。相同版本不重复记录发布；新增复制文件数、复制字节、复用数量和构建耗时日志。
- 无效旧清单移入快照仓库的 `quarantine` 保留并汇总告警，避免下次启动重新解析同一批旧清单。
- 玩家 NBT 完整校验后保存原始 gzip 字节，取消重复压缩，保留原锁、两次 force、原子替换及退出顺序。
- 元数据自然检查点改为单份在途的后台任务，服务器线程发布完成结果；慢写时不积压采样。命令、任期和关闭仍等待正确顺序并完成耐久提交。普通快照/ACK/state/追赶读取已发布版本，不等待后台磁盘；未来计划事件未到期时也不进入等待。

验证记录：

1. 环境初始回归：未变化文件复制、重复刷新、旧清单隔离、连续通知饥饿和漏事件校验共 5 项在旧实现失败；修复后通过。审查发现的忙碌期间周期校验丢失也单独先红后绿。
2. 玩家数据分类 7 项先失败后通过；玩家原字节保存回归先发现 95 字节上传被重压为 81 字节，修复后相关 17 项通过。
3. 元数据后台读取锁回归先失败后通过；新增检查点有界/发布/失败/关闭/任期交错 7 项测试，以及未来计划事件 2 项回归。独立审查发现的计划任务和只读请求等待回流均已修正。
4. `.\gradlew.bat test build --no-parallel`：成功，139 个测试类、706 项测试、0 失败、0 错误、3 项需要显式开启的进程测试跳过。构建产物为 `build/libs/player_to_player-1.0.2.jar`。
5. `.\gradlew.bat test --tests '*MetadataProcessSmokeTest' -Pp2pMetadataSmoke -Pp2pSmokeJavaVersion=17 --no-parallel`：成功，Java 17 下真实中心服与两个计算 JVM，1 项通过，未跳过。覆盖命令幂等、连续补丁缺口恢复/快照回退、Boss 删除、边界渐变、计划事件、断线冻结及重新追赶。结果位于 `build/metadata-smoke/1793524495605/result.json`。
6. `git diff --check` 通过。分类/玩家持久化和环境/元数据并发修改均经独立代码审查，发现的问题已复查通过。

上述验证使用人工存档和本机进程，没有复跑真实玩家的两分钟负载，不能把它描述为实际 CPU 已下降某个比例。上线后可用新增的环境构建指标和相同游戏场景进一步对比。协议版本、消息类型、mixin 声明和存储格式未改变；中心、中转和客户端建议一并更新，以保证旧环境清单的处理规则一致。
